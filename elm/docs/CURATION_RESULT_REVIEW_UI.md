# r18 retained-result review (production dispatch unavailable)

The private review page exposes authenticated current-chat job metadata (`private.curation.jobs.list`), explicit full result reveal (`.get`) and individually confirmed proposal acceptance (`.accept`). There is no public job creation, fake-result import, prepare/execute/send or external-processing consent control. Jobs can currently be produced only through internal synthetic loopback qualification. Empty lists do not create example jobs. Attempted status is not proof of transport, billing or delivery.

Inspection may reveal sensitive source-bound model text. Full normalized proposal metadata, source references/hashes/quotes, source origin, sensitivity and model/unverified labels are rendered inertly. Bodies/results are retained locally as plaintext; no result purge is provided. Backend list is bounded to 16 and get refuses >64KiB rather than silently truncating.

Each proposal requires its own confirmation. The rendered job object/revision/index and owner are captured before staging; the displayed proposal is deep-copied. Confirm binds to the exact staged action and matching current job revision. The server receives job_id, proposal_index, expected_revision and confirm:true, not browser-edited candidate content. Backend verifies current owner and source freshness, rejects withdrawal/change and atomically guards accepted indexes. Accepted records remain pending with sensitivity preserved; final approval is separate. A source hash/quote establishes textual provenance, not model title/interpretation truth.

Accepted indexes and non-ready jobs cannot stage. Revealed jobs display accepted_records index-to-record-ID mappings for lost-response reconciliation without replay. Scope changes erase job bodies and invalidate delayed reads/confirmations. Failed or lost acceptance responses are uncertain, not retried. Refresh jobs and private records to reconcile; no automatic replay. The success receipt contains only record ID/state/sensitivity and explicitly says not approved. Project review has no job APIs.

Evidence: 69 controller tests (six new jobs tests) plus seven actual React SSR suites with synthetic adapters. private-job-review.html demonstrates real component rendering, not an installed native application. Synthetic fixtures are labeled; no paid API/network dispatch or live install/publication. No browser sandbox bypass. Production extraction remains unavailable despite local review UI support.

## r19 historical recipient display
Job reveal now displays only an explicit bounded primitive allowlist: provider, exact endpoint, requested model, credential mode, optional synthetic slot/version and canonical payload SHA-256. It omits route hashes, credential hashes/values, owner hashes, tokens and all unknown fields. Text is inert, never a clickable endpoint. The receipt is historical/requested metadata, not active permission, proof of delivery or proof the actual provider executed a particular model. A synthetic dedicated slot/version contract is locally qualified, but no production secret store or authenticated HTTPS credential route is configured. No send controls added.

Updated evidence: 70 controller tests, including malformed/nested receipt rejection and secret/unknown-field exclusion; seven rebuilt SSR suites verify receipt escaping and omissions. Existing synthetic component/native-browser limitations remain unchanged.
